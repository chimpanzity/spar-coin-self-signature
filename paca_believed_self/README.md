# PACA believed-self generator pilot (2026-10-11)

Does believing that a sequence is generated by another instance of yourself change how an LLM uses the observed history
to forecast the next event? The task is the PACA minimalist forecasting task: the model chooses where the blue circle
will land, TRIANGLE or STAR. One sentence is prepended to the system prompt:

- believed self: *"Another instance of your model is generating the sequence of blue circle landings."*
- believed other: *"An instance of a different language model is generating the sequence of blue circle landings."*

The landings actually come from Proteus or an IID fair coin, and this is hidden in both conditions. That gives a 2 × 2
design within each model, with one 200-trial session per cell. The model sees the last 25 trials, while Proteus
conditions on the full session.

**Ran:** Fable and Astra, 8 sessions, 1,600 calls, all complete, $22.44 including preflight. **Qwen was not run**: at
PACA's default reasoning, each forecast took ~30k tokens and ~10 minutes (decision recorded in
`data/believed_self_pilot/APPROVAL.md`).

**Result (descriptive; one session per cell):**
- No consistent effect of the believed-self frame on accuracy.
- Against the coin, both models bet against a repeat of the last landing.
- The frame pushes the two models in opposite directions on that history dependence, in both environments:
  - Fable expects *more* switching when told the generator is itself (circle lag-1 coefficient: coin −0.80 vs −0.39).
  - Astra expects *less* (coin −0.30 vs −0.63).

  The coin pairs saw identical coin sequences. Session-to-session noise could produce differences of this size, so
  this is a candidate effect to replicate, not a finding.

Full report: [`data/believed_self_pilot/analysis/REPORT.md`](data/believed_self_pilot/analysis/REPORT.md).

## Layout and provenance

This folder mirrors the layout of the local PACA harness (`PACA_implicit/`) it ran in, so the code runs here unchanged.

| file | origin |
|---|---|
| `task/believed_self.py`, `task/run_believed_self_pilot.py`, `task/analyze_believed_self.py`, `tests/test_believed_self.py` | written for this pilot |
| `task/protean_committed.py` | PACA's Proteus (Lee et al. 2004, Algorithm 2), unchanged |
| `task/prompts.py`, `task/prime.py`, `task/api_client.py`, `task/analyze_pilot.py` | PACA harness files, unchanged |
| `code/verify_brown_rosenthal.py` | PACA's Brown–Rosenthal implementation, unchanged |
| `data/believed_self_pilot/` | manifest, approval and decisions, preflight, per-session raw `trials.jsonl` / `attempts.jsonl` / `session_meta.json`, `analysis/` (report, CSVs, figures) |

The PACA files are byte-identical to the copies the pilot ran with. The offline validation's fake-run data and the
outputs zip are not committed.

Note on PACA's Brown–Rosenthal script: its Outcome block uses own × outcome. Under ±1 coding in matching pennies, that
term is identical to the opponent lag, so the block can add no information. This pilot reports an outcome main effect
instead (see the analysis docstring).

## Running

Needs numpy, pandas, scipy, matplotlib and openai, plus `OPENROUTER_API_KEY` for live calls.

```bash
python -m pytest -q tests/test_believed_self.py          # offline
python task/run_believed_self_pilot.py validate           # offline full dry run
python task/analyze_believed_self.py                      # re-analyse from raw logs
python task/run_believed_self_pilot.py run --live         # needs APPROVAL.md approval line; resumable
```
